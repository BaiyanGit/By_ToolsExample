# ByFramework 最终架构设计总览

## 一、项目定位

ByFramework 是一个面向 Unity 的通用框架。

它不是某一个项目的脚手架，而是一套可长期复用、可持续扩展、可支持多类型 Unity 项目的底层框架。

主要面向：

```text
工业仿真
驾驶模拟
数字孪生
培训系统
管理系统
在线系统
多机协同系统
其它 Unity 项目
```

目标平台：

```text
Windows
Linux
```

长期支持方向：

```text
VR
多屏
多语言
BuildProfile
License
AssetBundle
SimulationServer
多机协同
客户端 / 服务端联调
```

------

# 二、核心设计思想

ByFramework 的核心思想是：

```text
Core 管生命线
Platform 管通用能力
FeatureModule 管业务实现
```

也就是：

```text
通用能力平台化
业务能力模块化
框架能力稳定化
```

框架不应该承载具体业务。

业务模块可以使用框架能力，但不能反向污染框架。

------

# 三、总体分层

ByFramework 最终分为三层：

```text
Core
↓
Platform
↓
FeatureModule
```

依赖规则：

```text
Core 不依赖 Platform

Platform 不依赖 FeatureModule

FeatureModule 可以依赖 Platform + Core
```

禁止：

```text
Core → Platform

Platform → FeatureModule
```

允许：

```text
FeatureModule → Platform

FeatureModule → Core
```

------

# 四、Core 层

## 4.1 Core 定位

Core 是框架生命线。

它只负责最基础、最稳定、最不带业务属性的能力。

Core 必须保持：

```text
少
稳
干净
长期不频繁变动
```

------

## 4.2 Core 包含模块

```text
FrameworkEntry
ThreadDispatcher
EventManager
FSMManager
Core Utilities
```

------

## 4.3 Core 生命周期

初始化顺序：

```text

↓

↓
EventManager
↓
FSMManager
```

关闭顺序：

```text

↓
EventManager
↓

↓

```

------

## 4.4 Core 职责

Core 负责：

```text

主线程调度
框架级事件
基础状态机

```

------

## 4.5 Core 不负责

```text

```

# 五、Platform 层

## 5.1 Platform 定位

Platform 是通用能力平台。

它负责 Unity 项目中大多数通用能力，但不包含具体行业业务。

Platform 必须保持：

```text
行业无关
项目无关
业务无关
可替换
可扩展
```

------

## 5.2 Platform 最终模块

```text
Platform
├─ PlatformServiceRegistry
├─ FrameworkConfig
├─ InputSystem
├─ UISystem
├─ UIThemeSystem
├─ DisplaySystem
├─ LocalizationSystem
├─ ResourceSystem
├─ SaveSystem
├─ BuildProfileSystem
├─ LicenseSystem
└─ NetworkSystem
```

说明：

```text
AssetBundle 属于 ResourceSystem

Http / Downloader 属于 NetworkSystem

UIThemeSystem 属于 UISystem 的主题子系统，也可以在目录上独立成模块

DOF 暂时不进入主架构，未来如有需要归入硬件接入相关模块
```

## 6.2 职责

## 18.10 NetworkCore 独立性原则

NetworkSystem 内部应明确拆分为：

```text
NetworkCore
NetworkSystem Adapter
```

其中：

```text
NetworkCore 是纯 C# 网络核心库

NetworkSystem Adapter 是 ByFramework 的适配层
```

### 18.10.1 NetworkCore 定位

NetworkCore 是可独立抽离、可单独复用的网络通信核心。

它应当可以脱离 ByFramework，被其它项目单独使用，例如：

```text
其它 Unity 项目
WPF 项目
WinForm 项目
Console 工具
ASP.NET 工具
独立服务器程序
设备调试工具
```

### 18.10.2 NetworkCore 包含能力

NetworkCore 可以包含：

```text
TCP
UDP
WebSocket
HTTP
Client
Server
Session
Protocol
Serialization
Connectivity
Downloader
```

其中 Socket 通信、Http 通信、大文件下载器都应优先保持在 NetworkCore 内部，保证以后可以独立打包成公共网络库。

### 18.10.3 NetworkCore 允许依赖

NetworkCore 只允许依赖：

```text
System
System.IO
System.Net
System.Net.Sockets
System.Threading
System.Threading.Tasks
System.Collections.Generic
基础序列化接口
基础日志接口
```

基础日志接口必须是抽象接口，不能直接依赖 ByFramework 的 Log 或 Unity 的 Debug.Log。

### 18.10.4 NetworkCore 禁止依赖

NetworkCore 禁止依赖：

```text
FrameworkEntry
PlatformServiceRegistry
FrameworkConfig
ThreadDispatcher
EventManager
FSMManager
ResourceSystem
SaveSystem
UISystem
UnityEngine
MonoBehaviour
ScriptableObject
GameObject
Scene
```

禁止在 NetworkCore 中出现：

```text
PlatformServiceRegistry.Get
EventManager.Publish
Debug.Log
MonoBehaviour.Start
MonoBehaviour.Update
ScriptableObject 配置
Unity 协程
```

### 18.10.5 正确依赖关系

正确关系：

```text
NetworkCore
        ↑
NetworkSystem Adapter
        ↑
PlatformServiceRegistry / FrameworkConfig / ThreadDispatcher / EventManager
        ↑
FeatureModule
```

也就是：

```text
ByFramework 依赖 NetworkCore

NetworkCore 不依赖 ByFramework
```

禁止关系：

```text
NetworkCore
        ↓
ByFramework Core / Platform
```

### 18.10.6 NetworkSystem Adapter 职责

NetworkSystem Adapter 位于：

```text
Platform/NetworkSystem
```

负责把 NetworkCore 接入 ByFramework。

职责包括：

```text
读取 FrameworkConfig 中的网络配置
注册 INetworkService 到 PlatformServiceRegistry
把 NetworkCore 的回调派发到 ThreadDispatcher
把连接事件转换为 EventManager 事件
统一参与 Platform 生命周期
向 FeatureModule 暴露框架侧网络服务接口
```

### 18.10.7 NetworkCore 独立发布目标

NetworkCore 最终应满足：

```text
可独立编译
可独立测试
可独立发布
可独立用于非 Unity 项目
可单独提供给其它框架或项目使用
```

因此 NetworkCore 的代码组织、命名空间、配置对象、日志对象、线程模型都要避免绑定 ByFramework。

建议命名空间方向：

```text
ByFramework.NetworkCore
```

或：

```text
ByFramework.Network
```

如果未来单独发布，可进一步拆成独立程序集：

```text
ByFramework.NetworkCore.dll
```

### 18.10.8 Socket 模块抽离要求

Socket 通信部分应优先保持可抽离。

Socket 核心只负责：

```text
连接
监听
断开
发送
接收
心跳
重连
会话
协议头
消息包
序列化
反序列化
```

Socket 核心不理解：

```text
车辆同步
机械臂同步
训练数据
场景状态
业务状态
```

业务消息由 FeatureModule 解释。

NetworkCore 只负责传输。

# 二十八、最终架构边界总结

```text
Core 管生命线
Platform 管通用能力
FeatureModule 管业务实现
```

具体边界：

```text
InputSystem 负责输入，不控制车辆

UISystem 负责界面，不写业务流程

UIThemeSystem 负责主题，不写业务逻辑

DisplaySystem 负责显示布局，不写场景业务

ResourceSystem 负责资源加载，不理解业务资源

AssetBundleProvider 负责加载 AB，不负责下载策略

AssetBundle Editor 负责打包 AB，不负责运行时业务

SaveSystem 负责保存读取，不理解业务数据

BuildProfileSystem 负责构建配置，不写运行时业务

LicenseSystem 负责授权判断，不绑定行业

NetworkSystem 负责通信，不做仿真同步

NetworkCore 必须保持纯 C#、低依赖、可独立抽离，不允许依赖 ByFramework Core / Platform 或 UnityEngine

NetworkSystem Adapter 负责把 NetworkCore 接入 PlatformServiceRegistry、FrameworkConfig、ThreadDispatcher 和 EventManager

Http 负责请求，不理解业务接口含义

Downloader 负责下载，不理解资源业务

SimulationSync 负责仿真同步，属于 FeatureModule

DOF 暂时不进入主架构，未来归入硬件接入方向
```
