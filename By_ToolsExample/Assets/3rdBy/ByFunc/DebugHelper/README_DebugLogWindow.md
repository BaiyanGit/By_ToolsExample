# DebugLogWindow

一个基于 **Unity IMGUI** 的运行时日志窗口工具，用于在游戏运行过程中查看、筛选、搜索、导出日志信息。  
适合开发调试、联调排查、真机测试、QA 回归时快速定位问题。

> 当前 README 对应版本：`DebugLogWindow_Optimized_v5.cs`

---

## 功能简介

`DebugLogWindow` 是一个运行时调试控制台，支持在游戏内实时查看 Unity 日志，并提供常用的日志操作能力，例如：

- 运行时打开 / 关闭日志窗口
- 自动收集 `Log / Warning / Error / Assert / Exception`
- 同时兼容**主线程**与**非主线程**日志收集
- 支持日志类型筛选
- 支持关键字搜索
- 支持折叠相同日志
- 支持显示 / 隐藏堆栈
- 支持单条日志展开堆栈
- 支持自动滚动到最新日志
- 支持暂停日志收集
- 支持导出当前视图到 `.txt`
- 支持点击复制日志内容 / 复制堆栈
- 支持窗口拖拽、右下角缩放
- 支持日志列表拖拽滚动
- 支持日志数量上限，避免长时间运行导致内存持续增长
- 自动创建实例，也兼容手动挂载，并内置重复实例保护

---

## 适用场景

这个工具适合以下情况：

- 需要在 **Editor PlayMode** 中快速查看实时日志
- 需要在 **PC / Android / iOS 真机运行时** 查看日志输出
- 项目中存在较多异步、线程、网络、资源加载等问题，需要在运行时观察错误与异常
- 测试人员不方便连接控制台，希望直接在游戏内查看关键日志
- 需要把当前筛选后的日志导出为文本，发给程序或测试同事分析

## 安装方式

### 1. 导入脚本
将 `DebugLogWindow_Optimized_v5.cs` 放入你的 Unity 工程中，例如：

```text
Assets/Scripts/Debug/DebugLogWindow_Optimized_v5.cs
```

### 2. 配置宏定义
本工具使用以下编译宏控制是否启用：

```csharp
DEVELOP_DEBUG
```

请在 Unity 中打开：

```text
Project Settings -> Player -> Scripting Define Symbols
```

把 `DEVELOP_DEBUG` 添加进去。

> 未添加该宏时，脚本不会参与编译，也不会在运行时创建日志窗口。

---

## 使用方法

### 自动创建
脚本默认支持运行时自动创建，无需手动挂载：

- 运行游戏后，工具会自动创建一个名为 `DebugLogWindow` 的对象
- 默认按快捷键可打开或关闭窗口

### 手动挂载
如果你更希望自己控制对象生命周期，也可以把脚本挂到任意 `GameObject` 上。

> 工具内部已经做了**重复实例保护**，即使同时启用了自动创建和手动挂载，也会自动避免多实例共存。

### 打开 / 关闭窗口
默认快捷键：

```text
F2
```

运行后按 `F2` 即可打开或关闭日志窗口。

---

## 支持的日志类型

工具会自动收集以下 Unity 日志：

- `Debug.Log`
- `Debug.LogWarning`
- `Debug.LogError`
- `Debug.Assert`
- `Exception / throw new Exception(...)`

内部使用：

```csharp
Application.logMessageReceivedThreaded
```

因此相较于只监听 `Application.logMessageReceived`，它对**非主线程日志**更友好。

## 界面说明

### 1. 标题栏
顶部显示窗口标题以及当前可见日志数量 / 缓存日志数量。

右上角提供关闭按钮：

- `✕`：关闭日志窗口

标题栏支持**拖拽移动整个窗口**。

---

### 2. 工具栏
工具栏包含以下能力：

- `暂停收集 / 继续收集`：临时停止或恢复日志收集
- `折叠`：将相同日志折叠统计显示
- `显示堆栈`：统一显示所有日志的堆栈信息
- `自动滚动`：有新日志时自动滚动到最新位置
- `最新在上 / 最早在上`：切换日志显示顺序
- `清空日志`：带二次确认的清空操作
- `导出当前视图`：把当前筛选结果导出成 `.txt`
- `打开目录`：打开导出目录

---

### 3. 类型筛选栏
支持分别筛选以下日志类型：

- `Log`
- `Warning`
- `Error`
- `Assert`
- `Exception`

每种类型后面会显示当前缓存中的数量统计。

---

### 4. 搜索栏
可按关键字搜索：

- 日志正文
- 堆栈信息

支持模糊匹配，忽略大小写。

---

### 5. 显示设置栏
支持运行时调整：

- **字号缩放**
- **窗口背景透明度**

适合在不同分辨率、不同场景背景下提升可读性。

---

### 6. 日志列表交互
每条日志支持以下操作：

- **单击正文**：复制该条日志内容
- **双击正文**：展开 / 收起该条日志的堆栈
- **复制内容**：复制该条日志正文
- **复制堆栈**：复制该条日志的堆栈信息
- **左侧拖拽手柄**：拖拽滚动整个日志列表

日志项使用不同图标与颜色区分类型：

- `ℹ`：Log
- `⚠`：Warning
- `✖`：Error
- `◆`：Assert
- `‼`：Exception

---

### 7. 窗口缩放
窗口右下角提供缩放手柄：

```text
◢
```

拖动后可自由调整窗口大小。

---

## 导出日志

点击：

```text
导出当前视图
```

会把当前界面上**可见的日志内容**导出为 `.txt` 文件。

导出内容会受到以下条件影响：

- 当前类型筛选
- 当前搜索关键字
- 当前折叠状态
- 当前排序方式

### 导出目录
导出路径为：

```csharp
Application.persistentDataPath + "/DebugLogs"
```

文件名格式示例：

```text
DebugLog_20260423_153045.txt
```

## Inspector 配置项说明

脚本提供了一组常用可配置字段：

### 基础显示
- `isShowWindow`：当前窗口是否显示
- `toggleKey`：打开 / 关闭窗口的快捷键
- `startVisible`：是否启动后默认显示窗口

### 日志缓存
- `maxLogCount`：最大日志缓存数量，超出后自动移除最旧日志

### 默认筛选
- `defaultShowLog`
- `defaultShowWarning`
- `defaultShowError`
- `defaultShowAssert`
- `defaultShowException`

### 默认显示行为
- `defaultShowStackTrace`
- `defaultCollapse`
- `defaultAutoScroll`
- `defaultNewestFirst`

### 窗口布局
- `minWindowSize`：最小窗口尺寸
- `defaultWindowSize`：默认窗口尺寸
- `uiScale`：UI 缩放比例
- `windowOpacity`：窗口透明度
- `headerBarHeight`：标题栏高度
- `entryMinHeight`：单条日志的最小高度

## 设计特点

### 1. 避免重复实例
工具支持自动创建，也兼容手动挂载，但内部使用单例保护，避免重复订阅日志回调导致日志重复记录。

### 2. 支持线程日志
使用 `Application.logMessageReceivedThreaded`，兼容多线程日志收集。

### 3. 控制长期运行开销
日志列表支持最大数量限制，避免长时间调试时无限增长。

### 4. 脏标记刷新
不是每来一条日志就立即整表重建，而是使用缓存脏标记机制减少不必要刷新。

### 5. 折叠更准确
折叠时不仅参考日志内容，也会结合类型与堆栈，避免不同来源的日志被错误合并。

## 注意事项

### 1. 本工具基于 IMGUI
由于使用的是 Unity 的 `OnGUI()`，它更适合开发调试与内网测试，不建议作为正式游戏 UI 的一部分长期暴露给最终玩家。

### 2. 建议只在调试环境启用
推荐通过 `DEVELOP_DEBUG` 宏控制，仅在：

- 编辑器调试
- 开发包
- 测试包

中启用。

### 3. 非常高频日志仍需克制
虽然工具内部已做日志数量限制和刷新优化，但如果你每帧大量刷日志，依然会影响运行性能。建议只在必要点打印。

### 4. 透明度不是越低越好
如果场景颜色比较复杂，建议把窗口透明度调高一些，以提高文字可读性。

## 常见问题

### Q1：为什么运行后看不到窗口？
先检查以下几项：

1. 是否添加了 `DEVELOP_DEBUG` 宏
2. 是否成功进入 PlayMode / 运行时环境
3. 是否按了默认快捷键 `F2`
4. 是否有别的脚本主动销毁了 `DebugLogWindow` 对象

---

### Q2：为什么有些日志以前收不到？
如果只使用 `Application.logMessageReceived`，某些非主线程日志可能不稳定。  
本工具已经改为 `Application.logMessageReceivedThreaded`，对线程日志更友好。

---

### Q3：导出的 TXT 为什么不是全部日志？
因为导出的是**当前视图**，会受到你当前界面状态影响，例如：

- 类型筛选
- 搜索关键字
- 折叠状态
- 排序方式

如果你想导出全部日志，请先恢复全部筛选条件再导出。

---

### Q4：为什么窗口看起来会挡住场景？
这是为了提高可读性。你可以在显示设置栏调整：

- 字号
- 透明度

来找到适合当前场景的显示效果。
