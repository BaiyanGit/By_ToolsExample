# 宏定义切换与打包工具 README

## 一、工具简介

这是一个用于 **Unity Editor** 的编辑器工具，主要解决以下几个问题：

- 管理多套宏定义模板
- 快速将指定模板应用到 Unity 的 `Scripting Define Symbols`
- 在切换宏定义后，按流程自动完成 **平台切换 → 编译 → 打包**
- 将宏定义管理与常用打包参数集中到同一个窗口中

菜单入口：

`Tools/宏定义切换与打包工具`

---

## 二、适用平台

当前版本支持以下平台：

- Windows
- WebGL
- Linux

> 注意：Unity 底层中，**Windows 与 Linux 共用 Standalone 的宏定义组**。  
> 因此本工具虽然允许分别保存 Windows 模式、Linux 模式，但真正写入 Unity 时，它们都会作用到同一组 Standalone `Scripting Define Symbols`。这是 Unity 本身的规则，不是工具限制。

---

## 三、脚本组成

请将以下脚本放到 `Assets/Editor/` 目录下：

- `MacroDefineBuildToolWindow.cs`：主窗口
- `MacroDefineBuildToolPopupWindows.cs`：弹窗窗口（保存模式 / 编辑模式）
- `MacroDefineBuildToolModels.cs`：数据结构、工具方法、构建逻辑
- `MacroDefineBuildToolProcessor.cs`：跨编译域的挂起流程处理器

配置文件会自动保存到：

`ProjectSettings/MacroDefineBuildToolConfig.json`

## 四、核心功能说明

### 1. 当前宏定义列表

该区域显示的是：

- **Unity 当前真正正在生效的宏定义**
- 如果当前内容与某个已保存模板完全一致，则标题会自动对应到该模板名称
- 如果当前没有匹配到模板，则显示为 **Unity当前宏定义**

特点：

- 列表支持折叠
- 只读展示，不在这里直接增删改单项宏定义
- 点击 **获取正在使用的宏定义**，会重新从 Unity 当前平台读取实际生效的宏定义

按钮说明：

#### 获取正在使用的宏定义
重新读取 Unity 当前活动平台的 `Scripting Define Symbols`，并刷新到当前宏定义列表。

#### 保存当前列表
将当前宏定义列表保存成一个新的宏定义模板，或覆盖同名同平台模板。

#### 更新
用于更新“当前正在使用的模板”。

规则：

- 若当前列表对应的模板正处于使用中，则按钮可点击
- 若当前列表对应的模板未处于使用中，则按钮不可点击

---

### 2. 已保存宏定义模式

该区域显示所有已保存的宏定义模板。

每个模板项包含：

- 折叠/展开查看宏定义明细
- 删除
- 应用
- 查看/编辑

显示规则：

- 若某模板的 **平台 + 宏定义集合** 与 Unity 当前实际生效的内容一致，则该模板前会显示 `✅`

#### 应用
点击后会：

1. 切换到对应平台（如有需要）
2. 将模板宏定义写入 Unity
3. 若勾选了“切换宏定义后直接打包”，则在编译完成后自动开始打包

#### 查看/编辑
会弹出独立窗口进行模板编辑。

> 当前版本中，编辑模板时**不会回填当前宏定义列表**。  
> 无论这个模板当前是否正在使用，修改模板只影响模板自身，不会主动改动主窗口左侧的当前宏定义列表。

---

### 3. 打包设置

该区域用于配置构建输出相关参数。

#### 当前平台
显示当前 Unity 的活动构建平台。

#### 打包路径
选择构建输出目录。

#### 构建名称
默认自动读取：

`PlayerSettings.productName`

如果为空，则会尝试退回到 `Application.productName`。

#### 构建版本
用于参与最终构建名称，也可选是否同步到：

`PlayerSettings.bundleVersion`

#### 高级选项

- **同步到 PlayerSettings.bundleVersion**  
  勾选后，打包前会将“构建版本”写入 `PlayerSettings.bundleVersion`

- **包名自动跟随系统时间**  
  最终构建名会追加时间戳，如：`20260422_153000`

- **平台参与构建名称（平台_项目名）**  
  平台短名会作为前缀参与命名，例如：
  - `Win_项目名`
  - `WebGL_项目名`
  - `Linux_项目名`

- **构建后自动运行**  
  打包成功后自动运行构建结果  
  > WebGL 不会使用 AutoRun

- **切换宏定义后直接打包**  
  在点击“应用”模板后，会自动进入：
  **切换平台 → 应用宏定义 → 等待编译完成 → 开始打包**

#### 预览
实时显示当前构建输出路径预览。

#### 立即打包（使用当前设置）
直接使用当前宏定义状态和当前打包配置执行一次完整打包流程。

## 五、命名规则

最终构建名生成规则如下：

`平台_项目名_v版本_时间`

实际是否包含其中某一段，取决于勾选项：

- 是否启用平台前缀
- 是否填写构建版本
- 是否启用时间戳

示例：

- `Win_Demo_v1.0.0`
- `WebGL_Demo_v1.0.0_20260422_153000`
- `Linux_Demo`

## 六、模板去重规则

本工具已对模板配置做重复拦截。

### 1. 宏定义项去重
在单个模板内部：

- 不允许存在重复宏定义
- 宏定义名会做标准化处理
- 宏定义格式不合法时会拦截

### 2. 模板配置去重
在模板列表中：

- 不允许存在 **同平台下、宏定义配置完全相同** 的模板
- 比较时会忽略顺序、大小写和空白差异

也就是说，以下两套配置会被视为相同：

- `A;B;C`
- `c ; a ; b`

## 七、使用流程示例

### 场景 1：把当前 Unity 宏定义保存成模板

1. 打开工具窗口
2. 点击 **获取正在使用的宏定义**
3. 确认左侧当前宏定义列表内容无误
4. 点击 **保存当前列表**
5. 输入模板名称与所属平台
6. 保存完成

### 场景 2：应用某个模板并立即打包

1. 在打包设置中勾选 **切换宏定义后直接打包**
2. 选择输出路径，设置构建名称与版本
3. 在“已保存宏定义模式”中点击某个模板的 **应用**
4. 工具将自动执行：
   - 切平台
   - 应用宏定义
   - 等待 Unity 编译完成
   - 自动打包

### 场景 3：只修改模板内容，不影响当前 Unity 状态

1. 在模板列表点击 **查看/编辑**
2. 修改模板名、平台或宏定义内容
3. 点击保存
4. 当前宏定义列表不会被回填修改
5. 只有当你显式点击 **应用** 时，才会真正写入 Unity

## 八、输出规则说明

不同平台的构建输出形式如下：

- **Windows**：输出为 `.exe`
- **Linux**：输出为可执行文件
- **WebGL**：输出为目录

工具会自动创建必要目录。

如果没有手动设置输出路径，工具会默认输出到项目根目录下的：

`Builds/`

## 九、注意事项

### 1. 必须有可用场景
打包前请确保 `Build Settings` 中至少有一个启用的场景，否则会打包失败。

### 2. 修改宏定义会触发编译
当工具应用新的宏定义后，Unity 通常会重新编译脚本。  
本工具已通过挂起流程处理该问题，因此可在编译完成后继续执行后续步骤。

### 3. 当前宏定义列表的定位
当前宏定义列表是“**Unity 实际状态展示区**”，不是模板编辑区。  
模板编辑请使用 **查看/编辑** 弹窗。

### 4. 平台切换可能需要时间
当应用模板的平台与当前活动平台不一致时，工具会先请求切换平台，完成后再继续后续步骤。

## 十、常见问题

### Q1：为什么 Windows 模板和 Linux 模板应用后宏定义会互相影响？
因为 Unity 底层将 Windows 与 Linux 都归类到 `Standalone` 宏定义组，所以它们共享同一组 `Scripting Define Symbols`。

### Q2：为什么编辑模板后，左侧当前宏定义列表没有跟着变化？
这是当前版本的设计行为。  
当前宏定义列表只显示 Unity 当前真实生效的状态，不会因为编辑模板而自动回填。

### Q3：为什么某些模板前面会显示 ✅？
表示该模板的 **平台 + 宏定义配置** 与当前 Unity 实际生效状态一致，也就是当前正在使用该模板配置。

### Q4：为什么“更新”按钮有时不能点？
只有当当前列表对应的是“正在使用中的模板”时，更新按钮才可点击。  
若当前列表并不是当前激活模板，更新按钮会被禁用。
